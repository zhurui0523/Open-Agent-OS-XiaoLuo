# 小逻 Windows 桌面版与云端服务方案

## 目标

普通用户安装 Windows 客户端后即可登录小逻，不需要在个人电脑上搭建 Web 服务、MySQL、OSS 网关或插件运行环境。客户端负责窗口、桌面集成和将来本地模型能力；远程服务负责身份、业务规则、协作、数据库、文件授权及云端任务。

## 运行边界

| 层 | 负责内容 | 禁止内容 |
| --- | --- | --- |
| Windows 客户端 | 展示远程工作台、系统文件选择、桌面通知、自动更新、未来本地模型桥接 | MySQL 账号、OSS AccessKey、服务端签名密钥 |
| 远程 Web / API | 登录、权限、画布、任务、插件授权、临时上传下载凭证 | 向客户端返回长期基础设施密钥 |
| MySQL | 用户、组织、画布、节点、任务和资产元数据 | 对普通客户端开放公网直连 |
| OSS | 图片、视频、音频、文档和插件包对象 | 向客户端暴露永久 AccessKey |
| 本地模型运行时（后续） | DeepSeek、MiniMax 等本地推理，通过 `127.0.0.1` 短期令牌受控调用 | 直接获得用户云端 Cookie 或基础设施密钥 |

## 请求路径

1. 桌面客户端只访问配置中的小逻 HTTPS 域名。
2. 用户在小逻页面登录，服务端设置安全 Cookie。
3. 业务 API 在服务端校验用户、企业、角色和资源归属。
4. 服务端连接 MySQL，客户端永远不直连数据库。
5. 文件上传与下载由服务端完成，或由服务端签发短时、单对象、限操作的 OSS URL。
6. 云端插件由服务端签发短期运行授权；本地插件和本地模型走独立 localhost 桥接协议。

## 上线门槛

- 站点外层访问策略允许普通用户访问登录页。
- 应用登录、角色与资源权限已开启，不能依赖站点“隐藏”保护业务数据。
- `/api/v2/health/live` 返回进程存活；`/api/v2/health/ready` 同时验证 MySQL 与 OSS。
- `pnpm desktop:verify` 通过后才能生成安装包。
- 构建日志、安装包、错误提示都不得输出密钥值。
- 曾进入聊天记录、截图或提交历史的数据库与 OSS 密钥必须轮换。

## 发布流程

1. 在远程运行环境配置 MySQL、OSS、认证和令牌签名密钥。
2. 执行数据库迁移与服务端测试。
3. 部署远程 Web / API，验证登录、`live`、`ready`、上传、下载和画布保存。
4. 将生产站点外层访问策略调整为普通用户可访问。
5. 执行 `pnpm desktop:verify` 与 `pnpm desktop:smoke:prod`。
6. 执行 `pnpm desktop:dist`，对生成的 Windows 安装程序签名并发布。

## 后续本地模型适配

本地模型不伪装成第三方云 API。桌面端启动一个仅监听 `127.0.0.1` 的本地模型代理，按统一能力协议报告模型、显存需求、上下文长度、模态和健康状态。远程服务只保存用户选择和任务元数据；原始素材是否上传由用户明确选择。云模型继续由远程服务代理，本地模型由桌面代理执行，两者在画布上共用任务接口，但在 UI 中明确标注“本地”与“云端”。
